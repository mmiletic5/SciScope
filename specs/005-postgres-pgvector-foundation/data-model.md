# Data Model: PostgreSQL and pgvector Foundation

## Global rules

- Every current corpus row is bound to one `delivery_import_id`.
- Hashes are lowercase 64-hex strings; delivery digests use `sha256:<hex>`.
- Delivered scalar scientific values are stored unchanged. DOI normalization is
  checked and rejected on mismatch, never silently applied.
- JSONB arrays retain delivered ordering. Import validation owns deep shape
  validation; database checks enforce container type where practical.
- All times generated by the database are audit metadata, not source metadata.
- `vector(1536)` is the only Phase A vector type.

## `delivery_imports`

| Field | Rule |
|---|---|
| `id` | Bigint identity primary key |
| `delivery_digest` | Required `sha256:` plus 64 lowercase hex; repeatable historically |
| `schema_version`, `contract_version` | Required nonempty text |
| `paper_count`, `section_count`, `chunk_count`, `vector_count` | Required nonnegative integers |
| `processing_versions`, `delivery_manifest` | Required JSON objects |
| `imported_at` | Required transaction timestamp |
| `is_active` | Required boolean; partial unique index permits at most one true row |

Successful activation rows are immutable through the application boundary.
Identical active reimport does not insert or update an audit row.

## `embedding_sets`

| Field | Rule |
|---|---|
| `id` | Bigint identity primary key |
| `delivery_import_id` | Required FK; unique so each import has one set |
| `provider` | Required; current value `openai` |
| `model` | Required; current value `text-embedding-3-small` |
| `dimensions` | Required; current value and check `1536` |
| `dtype` | Required; current value `float32-le` |
| `passage_prefix`, `query_prefix` | Required; current values empty |
| normalization fields | `normalization_declared` is the numeric target L2 norm (`1.0`); observed min/max and positive tolerance are stored separately. The source method string (`"l2"`) remains unchanged in `embedding_manifest` JSONB. |
| chunk/vector hashes | Required lowercase 64-hex |
| `embedding_model_revision` | Nullable; never invented |
| `embedding_manifest` | Required JSON object preserving manifest metadata |

## `papers`

`doi` is the primary key. Required fields are import ID, title, nonempty ordered
authors array, journal, publication date text, positive publication year,
article type, ordered subjects array, nonempty raw license and language, source
URL, retrieval timestamp text, and XML SHA256. A composite unique key on
`(delivery_import_id, doi)` supports same-import foreign keys.

DOI checks enforce lowercase DOI shape. Application validation additionally
requires `normalize_doi(incoming) == incoming`.

## `sections`

`section_id` is the primary key. Required fields are import ID, DOI, title, XML
SHA256, ordered nonempty section path, original heading (empty allowed), one
taxonomy-v0 normalized type, source locator, positive depth, and nonnegative
paragraph count. `parent_section_id` is nullable.

Relationships:

- `(delivery_import_id, doi)` references the matching paper.
- `(delivery_import_id, doi, parent_section_id)` references a section in the
  same import and DOI through a deferrable self-FK.

## `chunks`

`chunk_id` is a 64-hex primary key. Required fields are import ID, DOI, section
ID, positive ordinal, `paragraph` kind, taxonomy-v0 type, ordered section path,
nonempty exact text, text SHA256, nonempty ordered spans, source locator,
positive content-token count, hard-split boolean, ordered omissions, and exact
chunking/token-counter/template versions.

Relationships and uniqueness:

- Composite FK to the same-import paper and section.
- Unique `(section_id, ordinal)` for deterministic section order.
- The chunk locator and span relationships receive semantic validation before
  insert; the database preserves them without rewriting.

## `chunk_embeddings`

| Field | Rule |
|---|---|
| `embedding_set_id`, `chunk_id` | Composite primary key |
| `delivery_import_id` | Required and included in composite ownership FKs |
| `input_sha256` | Required lowercase 64-hex |
| `embedding` | Required `vector(1536)` |

Composite FKs bind the embedding set and chunk to the same delivery import.
There is exactly one embedding per active chunk and embedding set.

## Indexes

- Partial unique active-import index.
- Index every non-primary FK used for relationship checks.
- Paper year, journal, and `lower(language)`.
- Section DOI, parent, and normalized type.
- Chunk DOI, section, normalized type, and import ID.
- No FTS, HNSW, or IVFFlat index in Feature 005.

## State transitions

Feature 005 permits an empty database and defines inactive/active import state.
Feature 006 owns activation. Valid transitions are no active import to one
active import, and one active import to another within one transaction. The
database never permits two active imports.
