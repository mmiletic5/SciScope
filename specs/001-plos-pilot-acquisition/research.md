# Research: PLOS pilot acquisition

**Problem.** Find candidate PLOS honeybee research articles, let a human select 15–20, then retain their raw JATS XML and reproducible front-matter records. This is a Person 1 pilot, not section parsing or automated screening.

**Verified from official PLOS documentation (2026-11-14).** The [search-fields reference](https://api.plos.org/solr/search-fields/) names `id`, `title`, `abstract`, `article_type`, `journal`, `publication_date`, and `subject`, and lists `research article` as an article type. The [search-facets guide](https://api.plos.org/solr/search-facets/) says normal queries should filter with `fq=doc_type:full`. The [query examples](https://api.plos.org/solr/examples/) document `/search`, `q`, `fl`, `start`, `rows`, and `wt=json`. The [FAQ](https://api.plos.org/solr/faq) sets 10 requests/minute, 300/hour, 7,200/day, at most five concurrent connections per IP, a maximum of 100 returned rows/request, and allowance of five seconds for a search response. The [text-and-data-mining guide](https://api.plos.org/text-and-data-mining.html) documents an individual JATS XML example: `https://journals.plos.org/plosone/article/file?id=10.1371/journal.pone.0170929&type=manuscript` (its example uses HTTP; HTTPS is proposed for the pilot). It discourages bulk XML downloads and accepts small subsets identified through Solr.

**Approaches.** (1) Python 3.12 standard library `urllib`, `json`, `hashlib`, and `xml.etree.ElementTree`: no new package or license review; enough for a 15–20 article pilot, with explicit retry/rate logic and conservative XML handling. (2) Add an HTTP and JATS parsing library: may reduce code, but package/version/license/compatibility and added dependency need separate research and owner approval. (3) PLOS bulk corpus tooling: designed for the entire corpus and disproportionate to this manually screened pilot. **Recommendation:** (1), using the existing dev `pytest` for offline tests. No new dependency requested.

**NOT VERIFIED.** Official PLOS material checked here shows the XML URL for PLOS ONE only; journal-specific paths and HTTPS response behavior for other selected journals need live checks. The JATS `article-type` value `research-article` must be checked against live selected XML. No live API/XML response, actual paper eligibility, license, language, or topic spread was verified in this sandbox. The draft `docs/DATA_CONTRACT.json` is a later Paper/Section/Chunk contract and has not been approved for this pilot; Person 2 reviews any later mapping. The human class codebook is defined in `spec.md`.
