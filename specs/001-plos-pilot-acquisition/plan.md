# Implementation Plan: PLOS pilot acquisition

**Branch**: `001-plos-pilot-acquisition` | **Date**: 2026-11-14 | **Spec**: `specs/001-plos-pilot-acquisition/spec.md` | **Owner**: Person 1

## Summary and technical context

Build a small Python 3.12 CLI for `search` and `download`. `search` writes candidate records; a human commits a 15–20 DOI selection; `download` takes its DOI list only from that selection and looks up candidate journal and query provenance by normalized DOI in committed `candidates.jsonl` before writing raw JATS XML, a manifest, and front-matter JSONL.

## Design and data contracts

- Six independent arms: `title:"Apis mellifera"`, `abstract:"Apis mellifera"`, `title:"honey bee"`, `abstract:"honey bee"`, `title:honeybee`, `abstract:honeybee`. Persist exact `q`, both `fq` values, `numFound`, UTC query date, and candidate DOI per arm; combine candidates by normalized DOI while retaining every matching arm. Each candidate also carries Solr `id`, `title`, `journal`, `publication_date`, and `abstract` for screening, never as acquired metadata. `numFound` is a Solr hit count only. Page deterministically at no more than 100 rows/request; report any candidate cap as truncation rather than complete coverage.
- Human screening is authoritative. `screening.tsv` records only reviewed candidates with DOI, one of the six FR-003 codebook classes, short reason, and human-chosen topic. `selection.tsv` has exactly `doi`, `class`, `reason`, `topic`, `methods_checked`; it is a reviewed included-class subset. The validator enforces 15–20 unique normalized candidate DOIs, at least three distinct human-assigned topics, `methods_checked=yes` for `honey_bee_unqualified` (empty allowed for other included classes), and presence of every selected DOI in committed `data/pilot/candidates.jsonl`. Screening may stop when 15–20 are selected. Download takes DOIs only from `selection.tsv` and looks up journal and all matching query-arm provenance by normalized DOI in `candidates.jsonl`; candidate records never add DOIs to the download list.
- Normalize DOI by the exact FR-005 rules; retain original input and normalized DOI. URL `id` extraction uses URL parsing and one defensive percent-decode, rejecting ambiguous or missing IDs. Test at least 12 cases including prefix forms, encoded URL ID, trailing punctuation, balanced/unbalanced closers, invalid syntax, and duplicates.
- Journal route comes from selected DOI/journal context, then is checked against the returned XML DOI and journal; never construct an arbitrary host from input. The PLOS ONE route is documented; other journal routes remain **NOT VERIFIED** until live terminal checks. Enforce HTTPS and fixed PLOS hosts.
- Validate JATS structure and XML front matter before acceptance: selected normalized DOI matches XML DOI, JATS `article-type` is `research-article` (value **NOT VERIFIED** until the live run), language is English, and `<license>` supplies a nonempty license identifier or URL. Missing or contradictory fields fail visibly. Extract only title, author names, journal, publication date, article type, subjects, abstract, license, language; retain XML text order where inline markup occurs. No body/section extraction.
- Manifest JSONL entry: `doi`, `original_doi` (selection value), `source_url`, `retrieved_at` (UTC ISO 8601), `xml_sha256`, `license`, `raw_xml_path`, `query_provenance` array (`q`, `fq`, `numFound`, `date`) for every matching candidate arm. Metadata JSONL uses the same DOI and the nine specified front-matter fields. Candidate/selection keys and error labels are defined here, so separate data-model/contracts files are unnecessary for this isolated CLI pilot.

## Reliability, errors, and resume

Use sequential requests through one connection with at least 6.0 seconds between request starts, including retries, and a cap of 300 requests per process run across search or download. The published 10/minute, 300/hour, and 7,200/day limits apply across repeated runs and remain operator checks; five concurrent connections is an upper bound, while this design uses one. Return no more than 100 rows/search request and allow at least five seconds for a Solr response. Inject HTTP fetch and sleep/clock callables so offline tests use neither network nor real sleeping. Retry timeouts, 429, and transient 5xx with bounded exponential backoff and `Retry-After` when present; fail clearly on permanent HTTP, malformed JSON/XML, selection errors, or the per-run cap. Atomic per-article writes and deterministic DOI-based paths make interrupted runs resumable. On resume, compare existing DOI/digest: equal means duplicate/skip, different means conflict and preserve the old accepted record. Summary lists accepted, duplicate, conflict, failed, and pending DOIs. Never count a failed or incomplete article as acquired.
